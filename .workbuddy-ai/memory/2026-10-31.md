# 2026-10-31

## Android 进 CI（`build.yml` 加 android job）

背景：CI 一直只有 Windows / Linux / macOS / iOS，Android 从来没构建过。`app/android/` 是
**入库**的（跟其它平台「CI 里 flutter create 生成」不一样），所以 CI 直接 `flutter build apk`。

### 改动

1. **`app/android/app/src/main/AndroidManifest.xml`**（原来几乎是模板原样，装上去不能用）：
   - 加 `INTERNET`：debug / profile 的清单里有，release 的没有 → 正式包一直「连不上服务器」；
   - 加 `WAKE_LOCK` / `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_MEDIA_PLAYBACK` / `POST_NOTIFICATIONS`；
   - Activity 换成 `com.ryanheise.audioservice.AudioServiceActivity`（audio_service 要求 Activity 和
     前台服务共用同一个 FlutterEngine），所以删掉了空的 `MainActivity.kt`；
   - 加 `AudioService` 服务 + `MediaButtonReceiver`（少了 init 就报找不到服务）；
   - `usesCleartextTraffic="true"`：内网直连 `http://192.168.x.x:端口`。
2. **`app/android/app/build.gradle.kts`**：`key.properties` 存在就用正式 keystore，否则退回 debug。
   注意 **`plugins {}` 必须是脚本里第一个块**，import 可以放在它前面，其它语句不行。
3. **`build.yml`**：新 job `android`（ubuntu-latest + JDK 21 + Gradle 缓存），
   `flutter build apk --release --split-per-abi`，产物改名
   `tonicuisc-android-{arm64-v8a,armeabi-v7a,x86_64}.apk`，用 `apksigner --print-certs` 打印证书指纹；
   `release` job 的 `needs` 加上 android。
4. 文档：README 平台列表 / 构建命令 / CI 段新增「Android（APK）」，写清 4 个签名 secret。

### 坑 / 结论

- **debug 签名在 CI 上不稳定**：每个 runner 现生成 `~/.android/debug.keystore`，所以每次发版签名不同，
  跨版本覆盖安装报「签名不一致」。要连续升级必须配 `ANDROID_KEYSTORE_BASE64` 那四个 secret。
- `app/android/gradlew` / `gradle-wrapper.jar` 被 .gitignore 忽略，但 Flutter 构建时会用
  `injectGradleWrapperIfNeeded` 从 SDK 模板补，CI 不用管。
- 本机没有 Android SDK，**没能在本地真跑一次构建**；只做了 YAML 解析 + `bash -n` + 脚本逻辑模拟。
- bootstrap_platforms 脚本的注释里补了「android 不在这里生成」，免得以后误加进 platforms 把清单盖掉。
