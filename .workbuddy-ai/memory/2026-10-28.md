# 2026-10-28

## 两个 bug：进度条拖动归零 + 歌词折行变「两段」

### 1) 拖动进度条 / 点歌词 → 回到 0（App 和网页都有）

根因在**服务端**：`/api/stream/{id}` 未缓存时不管 `Range` 一律返回 200 + `Accept-Ranges: none`，
播放器跳不动，只能把进度条弹回 0。网页始终走 `/api/stream`，App 回退到中转流时也走它。

改法（`api/routes/media.py` + `services/downloads.py`）：
- `_range_start()` 取 Range 起点，`bytes=0-` 当「整段」（播放器第一个请求就长这样）；
- 起点 > 0 时把 `Range` 透给音源（`open_upstream(range_header=...)`），拿到 206 就
  `service.forward()` 原样转发 + 透 `Content-Range`/`Content-Length`，**这段不写缓存**（中间开始的字节拼进去会错位）；
- 音源不认 Range（回 200）时退回原来的 relay + 写缓存。

测试：`tests/test_api.py` 新增 3 个（206 透传、`bytes=0-` 仍走整段缓存、Range 传给音源）。

### 2) 长句折行看起来像「一句变两段」

整行一条 `linear-gradient`（web）/ 一个 `ShaderMask`（app），渐变横跨整个文本框；
折行后第二行从左边重新填充，像两段各自在扫。

改法：**逐词填充**。
- web：`renderLyrics` 给每个 word 建 `<span class="w">`，`updateLyricActive` 按
  `wordProgress(word, pos)` 设每个 span 的 `--p`；CSS 规则挪到 `.main-text.kara .w`。
- app：`_lyricMain` 改成 `Text.rich` + `_karaokeSpans()`：已唱/未唱用 TextSpan，
  正在唱的那个词用 WidgetSpan+ShaderMask 单独扫；`LyricWord.progressAt()` 放进模型里。

### 3) 顺带：网页不再自己删歌词行

`music.js` 里的 `dropCredits()`（按正则删开头 10 行像「词：xxx」的）整个删掉——
它会连正文一起吞，和服务端「只删歌名-歌手那一行、署名保留但不注音」的策略冲突。
App 端本来就没有这一步。

验证：`pytest` 332 passed；`dart analyze` 三个文件无问题。
（`flutter test` 在这个沙箱里起不来：`flutter_tester` WebSocket 连不上，环境限制。）

## 续：进度条点击仍失效 / 歌词滚动生硬 / 歌词区滚动条

### 进度条（根因：响应头还写着 Accept-Ranges: none）

上一轮只改了「请求侧」（把 Range 透给音源），但**首次那个 200 响应**还带
`Accept-Ranges: none`、也没有 `Content-Length`。浏览器据此判定整段不可跳，
点进度条时根本不发 Range，直接从 0 重来。

改法（`api/routes/media.py` 的 relay 分支）：`Accept-Ranges: bytes` + 透传
`Content-Length`。现在首次流也是「可跳的」，浏览器才会发 `Range: bytes=N-`，我们回 206。

另外客户端加了乐观位置（`state.seekPending`）：`seekTo` 后 `audio.currentTime` 要几帧
才真的挪过去，这段时间进度条/歌词高亮先用目标值，不再「跳过去又弹回来」。

### 歌词滚动

- `scrollbar-width: thin` → `none` + `::-webkit-scrollbar{display:none}`（截图右边那根）；
  同时 `overflow-x: hidden`。
- 不用 `scrollTo({behavior:'smooth'})`（~300ms 匀速、会被下一句硬打断），改成自己
  rAF 补间 easeOutCubic，时长按距离 260~620ms；用户滚轮/触摸时立刻 `stopLyricScroll()`。
- `updateLyricActive` 改用 `progressPosition()`，点歌词/拖进度条时高亮立刻跟上。

验证：pytest 332 passed（`bytes=0-` 那条断言改成 accept-ranges=bytes + content-length）。

## 续 2：宽屏改成「页面不滚，各面板自己滚」

现象：滚轮在右边歌词上滚，动的却是整页（左边列表跟着走）；右边还多一根页面滚动条。

根因：`.app`/`.main` 用的是 `min-height: 100dvh`，**整页在滚**；右侧 `.now-panel` 是
fixed + 内部 `.lyrics` 自己滚。两个滚动上下文并存，滚轮落到谁身上看运气。

改法（`music.css` 末尾 `@media (min-width: 1201px)`）：
- `html, body { height: 100%; overflow: hidden }` → 页面锁死，滚动条消失；
- `.main { height: 100dvh; overflow-y: auto; overscroll-behavior: contain;
  scrollbar-width: none }` → 左栏自己滚，也不显示滚动条；
- 窄屏（≤1200，单栏 + 抽屉式播放页）保持整页滚，不受影响。

配套 JS（`music.js`）——**别漏**，否则触底加载会失效：
- `DESKTOP_MQ = matchMedia('(min-width: 1201px)')`；
- `scrollHost()` / `scrollHostToTop()` / `scrollHostNearBottom()` 三个小工具，
  宽屏返回 `el.main`，窄屏返回 null（走 window）；
- `showView()` 里的 `window.scrollTo(0,0)` → `scrollHostToTop()`；
- 触底加载的 scroll 监听同时挂在 `window` 和 `el.main` 上（`.main` 的 scroll 不冒泡）。

## 续 3：web 歌词「慢半拍」对齐 App

用户：App 的实时歌词非常准时，web 有点拖拉。两边用的是同一份时间轴
（`line.start` / `word.s`，`indexOf` 算法也一模一样），所以差异只可能在**播放时钟**和**渲染**。

对照 App 的 `_displayPosition`（position 流 ~5Hz，用 `DateTime.now()` 差值补中间），
web 这边补了同样的东西：

- `playbackClock()`：`audio.currentTime` 只在值变化时重锚，两次采样之间按
  `performance.now()` 往前推（上限 0.3s，paused 时不推）。`currentTime` 每帧都变时行为不变。
- `progressPosition()` 改用 `playbackClock()`，`updateLyricActive` 也跟着用 → 高亮/填充同源。
- rAF 循环里顺带每 66ms 刷一次 `renderProgress()`（以前只靠 `timeupdate` 的 4Hz，
  进度条和时间文字是一秒四跳）。
- `timeupdate` 里加 `if (state.playing) startLyricLoop()` 兜底：rAF 循环中途断了会自动拉回来，
  否则歌词退化成 4Hz。
- `.lyric-line` 的 `color` 过渡 0.2s → 0.1s（换行时颜色「啪」地到位，不再慢慢变蓝）。
- 歌词滚动补间 260~620ms → 200~460ms（更快到位）。

如果还觉得慢，下一步只能上「歌词延迟偏移」（±0.5s 可调）——那属于音频输出延迟补偿，
跟时间轴无关。

## 续 4：web「展开正在播放」在宽屏是真·全屏了

以前 `pbExpand` → `openNowPanel()` 只是给 `.now-panel` 加 `is-open`：
窄屏是抽屉（有用），**宽屏面板本来就一直显示，加了等于没加**——所以「全屏不能用」。

现在 `@media (min-width: 1201px)` 下 `.now-panel.is-open` 直接 `inset: 0` 铺满整屏，
内部 `.now-body` 改成 grid：左列封面 + 标题 + 操作，右列歌词（`grid-area: 1/2/5/3`）。

复用的东西（没写新逻辑）：
- 进度条/时间：`el.nowSeek` / `nowCur` / `nowDur` 本来就在 `renderProgress` 和拖拽绑定里；
- 播放控制：`.now-controls`（原 `.mobile-only`）在 `is-open` 下用 `display:flex !important` 打开，
  `nowPlay/nowPrev/nowNext/nowMode/nowQueue2` 的绑定和 `renderNow()` 都是现成的；
- 关闭：`#nowClose`（原来只在 ≤1200 显示）+ Esc（`bindKeyboard` 里本来就有）。

新增 `recenterLyric()`：开/关全屏后面板尺寸变了，rAF 一帧后 `updateLyricActive(true)`
把当前这句重新居中（不然还停在旧容器的滚动位置）。

坑：`.lyric-lines { padding: 36% 4px }` 的百分比是按**宽度**算的，全屏右栏很宽会撑出巨大留白，
全屏下改成 `padding: 22vh 4px`。

## 续 5：全屏比例调整（截图反馈）

第一版全屏左右比例不好看：左栏 360 挤在最左、歌词横跨 1300px（当前句的底色拉成一整条色带）、
左栏内容全堆在顶部、下面一大块空。

调整（仍只在 `min-width: 1201px` 的 `.now-panel.is-open` 下）：
- `.now-body` 加 `max-width: 1280px; margin: 0 auto` → 超宽屏整块居中，不再拉成一条长带；
- 左栏 `clamp(300px, 30vw, 460px)`，封面 `min(100%, 420px)`；
- 行模板 `1fr auto auto auto 1fr` → 左栏那摞（封面/标题/操作）自动垂直居中；
- 歌词块 `max-width: 720px` + `display:flex; flex-direction:column; align-items:center`
  → 每句按内容宽度撑开，当前句底色贴着文字，不再横贯全屏；
- 全屏字号 15.5 / 当前句 18；
- `.now-controls` 也限 1280 并居中，和上面内容对齐。

## 续 6：全屏播放页（动效 + 音量 + 黑胶样式）

需求四条，都在 web 的 `.now-panel.is-open`（宽屏全屏页）里：

1. **展开/收起动效**：`@keyframes now-panel-in/out`（translateY(100%)↔0）。
   收起不能直接摘 `is-open`（会硬切回侧栏），所以 `closeNowPanel` 先加 `is-closing`
   播 300ms 再摘；`openNowPanel` 里 `clearTimeout` 防止半路重开打架。
   只在 `@media (min-width:1201px)` 生效，窄屏抽屉还是原来的 transform 过渡。
2. **音量**：`#nowVolume` / `#nowMute`（在 `.now-controls` 里，只有这页显示），
   和 `pbVolume`/`pbMute` 共用 `state.volume`/`state.muted`；`renderVolume()` 改成遍历
   `[pbVolume, nowVolume]` 和 `[pbMute, nowMute]`。
3. **样式切换按钮**：`#nowStyle` 放在队列按钮后面（`.now-controls` 内 → 只有这页有），
   切 `.now-panel.is-vinyl`，存 `localStorage['tonicuisc.nowStyle']`，`initNowStyle()` 恢复。
4. **黑胶**：`.now-cover` 变圆盘 + `repeating-radial-gradient` 纹路，封面缩成中间圆标，
   `.vinyl-disc` 播放时 `vinyl-spin` 旋转（`is-playing` 由 `renderNow()` 挂）；
   唱臂 `.now-tonearm` 在 `.vinyl-disc` **外面**（不然跟着转），
   `transform: rotate(calc(10deg + var(--arm) * 26deg))`，`--arm` 在 `renderProgress()` 里
   按 `position / duration` 写，所以随进度实时扫。

两个坑：
- `.now-cover` 原本 `overflow: hidden`，会把伸出去的唱臂裁掉 → 黑胶模式下改 `visible`，
  裁切交给 `.vinyl-disc` 自己（`border-radius: 50%`）。
- 黑胶样式全部写成 `.now-panel.is-open.is-vinyl ...`，侧栏永远保持方形封面
  （否则唱臂会盖住侧栏标题）。
